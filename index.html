A plain-language guide

把 SUICE Agent 想成一个会查证的遥感助手

它不是“一个模型直接回答所有问题”，而是先判断任务，再调用数据工具，必要时让 SUICE 看图，最后把证据整理成答案。

模型负责想和看，Agent 负责决定先做什么、再做什么。

一条请求是怎么跑完的

下面这条链就是系统的主循环。每一步都有自己的职责，Planner 不会亲自替代数据库或视觉模型。

01 · 规划

理解问题

判断这是定位、统计、看图、变化检测，还是精确量算。

02 · 选择

挑工具

决定调用区域定位、检索、POI、影像或计算工具。

03 · 取证

先查数据

用便宜而确定的数据库和索引先缩小范围。

04 · 看图

调用 SUICE

只对关键候选影像做视觉核验，获得像素证据。

05 · 收尾

汇总答案

区分候选、确认、估算和精确值，再向用户说明。

三个角色，各自做什么

脑

规划器

像项目负责人。它读取问题和已有结果，每轮只决定一个下一步动作，直到证据够用。

箱

工具箱

像一组专业部门：地图负责定位，数据库负责统计，检索负责找候选，量算工具负责算面积和长度。

眼

SUICE 视觉模型

像遥感专家。它把图片转成空间证据，再交给语言模型组织成可读的回答。

Agent 不是一次回答，而是一台状态机

每次工具返回结果后，系统都会回到“判断下一步”这一状态。它不会因为找到一个候选就自动宣布结论。

STATE 01

接收问题

提取地点、目标、时间、范围和用户想要的结果。

→
STATE 02

选择动作

Planner 输出一个工具调用，或判断当前证据已经足够。

→
STATE 03

执行并观察

工具返回结果，系统记录成功、失败、候选和核验状态。

→
STATE 04

收尾或继续

证据充分就输出答案；证据不足就带着新观测再规划一次。

用户：海淀区附近有哪些篮球场？
Planner：{"tool":"aoi.resolve","args":{"name":"海淀区"}}
工具：区域已定位，得到中心坐标和范围
Planner：{"tool":"retrieve.by_concept","args":{"concept":"篮球场","aoi":"已定位区域"}}
工具：返回 20 个候选位置，尚未全部核验
Planner：{"tool":"retrieve.verify","args":{"k":10,"backend":"suice"}}
工具：核验 10 块影像，确认 5 块存在目标
最终：输出“5 个已确认，其他为未核验候选”。

当前案例
“这张图里有没有篮球场？”

问题只需要看一张图，Agent 会直接进入视觉路径。

Agent 为什么要区分三种证据

遥感查询中最容易出错的地方，是把“搜到过”误写成“确认存在”。Agent 会把证据分层保存。

候选证据

来自索引、SAE 或相似度检索。说明“可能相关”，适合用来缩小范围。

视觉核验证据

SUICE 实际看过对应影像，并给出“有、没有或不确定”的判断。

确定性证据

来自 POI、行政边界、像素量算等规则工具，适合支撑数字和位置。

回答边界：如果只检查了部分候选，Agent 应该说“已核验的部分中确认了……”，不能说成整个区域的完整总数。

SUICE 不替换语言模型，而是给语言模型增加一条遥感侧输入。语言能力继续由宿主模型负责。

普通文字沿用 Qwen 原来的处理路径，语言能力保持不变。
视觉插槽问题后面放置几个内部的 <EO_TILE> 位置，表示“这里接收图片证据”。

一次看图生成分成两个阶段

理解这一点，就能明白为什么 SUICE 可以把视觉证据接入 Qwen，又不必改写整个生成流程。

第一阶段：Prefill，先读完整问题和图片

  • 读取问题、上下文和 <EO_TILE> 视觉插槽。
  • DINOv3 产生图片的空间 patch 特征。
  • EO 专家在少数关键层计算视觉增量。
  • 视觉增量写入当前序列的隐藏状态和缓存。

第二阶段：Decode，逐字生成答案

  • 模型根据已经读入的上下文逐 token 生成。
  • 新生成的普通文字不再重复计算 EO 专家。
  • 语言模型继续负责连贯表达、格式和结论。
  • 如果需要更多证据，则由 Agent 开启下一轮工具调用。

为什么要这样设计

先筛选，再看图

城市范围可能有成千上万张影像。先用数据库和索引找候选，再让 SUICE 精看，速度和成本都更可控。

能计算的不要猜

面积、长度、距离交给确定性工具。SUICE 判断目标位置，工具负责把数字算准。

证据不够就继续查

Agent 会把工具结果放回上下文。如果发现只是候选而没有核验，它可以继续调用视觉工具。

保留原模型能力

SUICE 是加法式专家。没有遥感证据时，宿主模型仍按原来的语言路径工作。

一句话记忆：Planner 决定“做什么”，工具执行“怎么查”，SUICE 负责“看图”，宿主模型负责“说清楚”。
